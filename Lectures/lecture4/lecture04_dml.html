Where we are going

Last time, we fixed an identification strategy — conditional ignorability given \(X\) — and asked how to construct the comparison: matching or weighting.

Today we keep the same identification strategy and ask a different question:

What can flexible estimation repair, and what identification failures remain untouched?

We will focus on:

  • outcome regression and inverse-probability weighting as two routes to the same estimand;
  • augmented IPW and double robustness;
  • what happens when \(X\) is high-dimensional;
  • why naive plug-in machine learning breaks inference;
  • Neyman orthogonality and cross-fitting; and
  • double/debiased machine learning (DML).

Start where we left off

Suppose our adjustment set \(X\) satisfies conditional ignorability:

\[ (Y(1),Y(0)) \perp D \mid X, \]

with overlap:

\[ 0 < P(D=1 \mid X) < 1. \]

This assumption is doing all the causal work.

Everything today — regression, weighting, machine learning, cross-fitting — is about estimating a quantity that is already identified.

No estimator, however flexible, creates identification that was not there.

Two ways to use the same identification result

Ignorability implies

\[ E[Y(1)] = E_X\big[E[Y \mid D=1, X]\big], \qquad E[Y(0)] = E_X\big[E[Y \mid D=0, X]\big]. \]

This single equality licenses two different estimation strategies:

  1. Outcome regression (OR): model \(E[Y \mid D, X]\) directly, then average predictions over \(X\).
  2. Inverse-probability weighting (IPW): model \(P(D=1\mid X)\), then reweight observed outcomes.

Both target the same estimand. Neither is “more identified” than the other.

Outcome regression

Let \(\mu_1(X) = E[Y \mid D=1, X]\) and \(\mu_0(X) = E[Y \mid D=0, X]\).

\[ \hat\tau_{OR} = \frac{1}{n}\sum_{i=1}^n \big(\hat\mu_1(X_i) - \hat\mu_0(X_i)\big) \]

What has to go right: \(\hat\mu_1, \hat\mu_0\) must be correctly specified (or converge fast enough — more on exactly what that means next).

Failure mode: misspecify the outcome model in regions with few treated (or few control) units, and the extrapolation is invisible in the fit statistics.

Inverse-probability weighting

Let \(\pi(X) = P(D=1 \mid X)\).

\[ \hat\tau_{IPW} = \frac{1}{n}\sum_{i=1}^n \left(\frac{D_i Y_i}{\hat\pi(X_i)} - \frac{(1-D_i) Y_i}{1-\hat\pi(X_i)}\right) \]

What has to go right: \(\hat\pi(X)\) must be correctly specified, and estimated propensities must stay bounded away from 0 and 1.

Failure mode: near-zero \(\hat\pi(X_i)\) or \(1-\hat\pi(X_i)\) produces enormous weights and explodes the variance — the same overlap problem from last lecture, now visible as instability rather than as a diagnostic plot.

Augmented IPW: combine both

\[ \hat\tau_{AIPW} = \frac{1}{n}\sum_{i=1}^n \Bigg[ \hat\mu_1(X_i) - \hat\mu_0(X_i) + \frac{D_i\big(Y_i - \hat\mu_1(X_i)\big)}{\hat\pi(X_i)} - \frac{(1-D_i)\big(Y_i - \hat\mu_0(X_i)\big)}{1-\hat\pi(X_i)} \Bigg] \]

This is the outcome-regression estimate plus a bias-correction term built from the propensity model.

\[ \underbrace{\hat\mu_1(X_i) - \hat\mu_0(X_i)}_{\text{outcome regression}} \;+\; \underbrace{\frac{D_i(Y_i - \hat\mu_1(X_i))}{\hat\pi(X_i)} - \frac{(1-D_i)(Y_i - \hat\mu_0(X_i))}{1-\hat\pi(X_i)}}_{\text{bias correction}} \]

  • \(D_i(Y_i - \hat\mu_1(X_i))\) is the treated unit’s residual switched off for controls by \(D_i\).
  • Dividing by \(\hat\pi(X_i)\) jacks that residual up:
  • The mirror-image term does the same for controls.

How this corrects mistakes

  • If \(\hat\mu_1,\hat\mu_0\) are correct, then \(E[Y_i - \hat{\mu}_1(X_i)] = 0\), so correction just gives variance
  • If \(\hat\mu_1,\hat\mu_0\) are wrong but \(\hat\pi\) is right, the residuals systematically encode whatever the outcome model missed. The reweighted average of those residuals estimates exactly that missing piece and adds it back in.

Proof: why the reweighting recovers exactly the missing piece

Condition on \(X\). Since \(E[Y\mid X,D=1]=\mu_1(X)\) — the true conditional mean, not \(\hat\mu_1\):

\[ E\big[D(Y-\hat\mu_1(X)) \mid X\big] = \pi(X)\big(\mu_1(X)-\hat\mu_1(X)\big) \]

Divide by \(\pi(X)\) — exactly what the correction term does:

\[ E\left[\frac{D(Y-\hat\mu_1(X))}{\pi(X)} \,\middle|\, X\right] = \mu_1(X) - \hat\mu_1(X) \]

Average over \(X\), then add back \(E[\hat\mu_1(X)]\):

\[ E[\hat\mu_1(X)] + E_X\big[\mu_1(X)-\hat\mu_1(X)\big] = E_X[\mu_1(X)] = E[Y(1)] \]

The \(1/\pi(X)\) weighting is what makes this exact: it scales up each treated unit’s residual by how rare treatment was at that unit’s \(X\), reconstructing the population-wide gap — not just the average gap within the treated subsample.

This is why \(\hat\pi(X)\) needs to be correct here: get it wrong, and the reweighting misrepresents which treated units should stand in for more of the population, and the cancellation above fails.

Double robustness

AIPW is consistent if either \(\hat\mu_d(X)\) or \(\hat\pi(X)\) is correctly specified — not necessarily both.

\[ \boxed{ \text{Correct } \mu(X) \ \text{ OR } \ \text{Correct } \pi(X) \ \Longrightarrow\ \hat\tau_{AIPW} \xrightarrow{p} \tau } \]

Two independent chances to get the nuisance functions right.

This is still a statement about estimation, conditional on ignorability. It is not a second identification strategy.

Where high-dimensional \(X\) enters

Conditioning arguments from Lecture 2 often demand a large adjustment set: many covariates, interactions, nonlinearities, possibly more parameters than observations.

Parametric \(\hat\mu(X)\) and \(\hat\pi(X)\) (e.g., linear/logistic) will be misspecified in exactly the settings where ignorability is most defensible.

The natural response: use flexible, machine-learning estimators (random forests, boosting, lasso, neural nets) for \(\hat\mu(X)\) and \(\hat\pi(X)\).

This creates a new problem — not a causal one, a statistical one.

Why naive ML plug-in fails: overview

Plug flexible ML estimates of \(\hat\mu(X)\), \(\hat\pi(X)\) directly into \(\hat\tau_{OR}\) or \(\hat\tau_{IPW}\) (or even AIPW) and re-estimate \(\tau\) on the same data used to fit the nuisance models.

Two things go wrong simultaneously:

  1. Regularization/overfitting bias. ML estimators are tuned to minimize prediction error, not to make the downstream causal estimate unbiased.
  2. Slow convergence. Flexible estimators converge at rates like \(n^{-1/4}\), not \(n^{-1/2}\) — too slow for the causal estimate to be \(\sqrt{n}\)-consistent.

Overfitting bias, concretely

Fit \(\hat\mu(X)\) by (say) a random forest on the full sample, then evaluate \(Y_i - \hat\mu(X_i)\) on the same units used to train it.

Residuals are mechanically shrunk toward zero — the model partly memorized \(Y_i\).

Any causal contrast built from these residuals (e.g., the AIPW correction term) inherits this shrinkage as bias that does not vanish as \(n \to \infty\) at the usual rate.

The problem is not that ML predicts \(Y\) poorly. It predicts \(Y\) too well, on the wrong sample.

Slow convergence, concretely

Formally, the parametric-vs-ML gap:

Parametric estimators: \(\hat\mu(X) - \mu(X) = O_p(n^{-1/2})\).

Flexible ML estimators: \(\hat\mu(X) - \mu(X) = O_p(n^{-1/4})\) (or slower), because they are trading bias for variance across a large function space.

A causal estimator built by plugging in \(\hat\mu, \hat\pi\) naively inherits an error of order

\[ O_p(n^{-1/4}) \times O_p(n^{-1/4}) = O_p(n^{-1/2}) \]

only if the score is well-behaved. For a naive (non-orthogonal) score, first-order nuisance error passes through directly, and the causal estimate converges at the ML rate — too slow for standard inference.

What does it mean for a function to converge?

\(\mu(X)\) is a function, not a single number — so “how close is \(\hat\mu\) to \(\mu\)?” is not as simple as comparing two numbers.

It is tempting to answer this by looking at residuals, \(Y_i - \hat\mu(X_i)\). This is the wrong quantity. The residual mixes two very different things:

\[ \underbrace{Y - \hat\mu(X)}_{\text{residual}} = \underbrace{Y - \mu(X)}_{\text{irreducible noise } \varepsilon} + \underbrace{\mu(X) - \hat\mu(X)}_{\text{estimation error}} \]

  • \(\varepsilon\) is genuine unpredictable variation in \(Y\) given \(X\). It never shrinks, no matter how good your estimator is or how much data you collect.
  • \(\mu(X) - \hat\mu(X)\) is the gap between your fitted function and the truth. This is the only piece that shrinks with more data — and it is the only piece “convergence” refers to.

Small residuals do not mean \(\hat\mu\) is close to \(\mu\). A model can have tiny residuals by memorizing noise, not by learning the truth.

Turning a function-to-function gap into one number

We can’t observe \(\mu(X) - \hat\mu(X)\) directly (\(\mu\) is unknown), but we can define what we mean by “close”:

\[ \|\hat\mu - \mu\|^2 = E_X\big[(\hat\mu(X) - \mu(X))^2\big] \]

In words: average, over the population distribution of \(X\), the squared gap between the fitted function and the true function at each \(X\).

This is a single number that summarizes how good \(\hat\mu\) is as an approximation to the whole function \(\mu\) — not how well it fits any particular sample.

“Converges fast enough” means: as \(n\) grows, does \(\|\hat\mu - \mu\|^2\) shrink, and how quickly?

Why flexible estimators converge more slowly

Think about what more data buys you, in each case.

A correctly-specified low-dimensional model (e.g., linear regression with the right functional form) has only a handful of unknowns — a few coefficients. Every additional observation sharpens all of them simultaneously. Estimation error shrinks proportional to \(1/\sqrt{n}\): quadruple your sample, and error roughly halves.

A flexible ML estimator (random forest, boosting) is approximating an unknown, possibly complicated function while also guarding against overfitting to noise. Part of every new observation goes toward controlling model complexity rather than purely sharpening the fit. Error shrinks much more slowly — often close to \(1/n^{1/4}\).

Sample size Error, parametric (\(\propto n^{-1/2}\)) Error, ML (\(\propto n^{-1/4}\))
100 0.10 0.32
1,600 (16×) 0.025 0.16
25,600 (256×) 0.006 0.08

Same growth in \(n\); wildly different shrinkage in error. This is the trade-off “converge fast enough” is asking about.

What we actually need

We want an estimator of \(\tau\) that:

  1. tolerates \(n^{-1/4}\)-rate nuisance estimation, and
  2. still converges to \(\tau\) at rate \(n^{-1/2}\), so that standard confidence intervals are valid.

Two ingredients deliver this:

  • Neyman orthogonality — a score function whose sensitivity to small nuisance errors is zero to first order.
  • Cross-fitting — using different data to estimate nuisance functions than to evaluate the causal score, removing overfitting bias.

Neyman orthogonality: the idea

A moment condition \(\psi(W; \tau, \eta)\) (here \(\eta = (\mu_1,\mu_0,\pi)\)) is Neyman orthogonal if

\[ \left.\frac{\partial}{\partial \eta}\, E\big[\psi(W;\tau,\eta)\big]\right|_{\eta=\eta_0} = 0. \]

Small errors in \(\hat\eta\) move \(E[\psi]\) only at second order — errors multiplied by errors, not errors alone.

The AIPW score is exactly this kind of object: it was already built to be doubly robust, which is the finite-sample cousin of orthogonality.

Orthogonality does the heavy lifting

With an orthogonal score, the estimation error in \(\hat\tau\) from nuisance mis-estimation is bounded by a product of the outcome-model error and the propensity-model error:

\[ O_p(n^{-1/4}) \times O_p(n^{-1/4}) = O_p(n^{-1/2}). \]

Two mediocre (slow) nuisance estimators combine into one good (fast) causal estimator — provided the score is orthogonal.

A non-orthogonal score (e.g., plain outcome regression alone) does not get this protection.

Orthogonality is not enough on its own

Orthogonality handles the rate problem in population.

It does not handle overfitting: if \(\hat\eta\) is estimated on the same data used to evaluate \(\psi\), the empirical process term does not vanish, and the second-order product bound fails in finite samples.

We still need to break the dependence between “the data that fit \(\hat\eta\)” and “the data that evaluate \(\psi\).”

That is cross-fitting.

Cross-fitting

  1. Split the sample into \(K\) folds (e.g., \(K=5\)).
  2. For each fold \(k\): estimate \(\hat\mu_1, \hat\mu_0, \hat\pi\) using only the other \(K-1\) folds.
  3. Evaluate the orthogonal score \(\psi\) for units in fold \(k\) using those out-of-fold nuisance estimates.
  4. Average the fold-specific estimates (or solve the pooled moment condition) to get \(\hat\tau\).

Every unit’s causal contribution is evaluated with nuisance functions it did not help fit.

Cross-fitting removes the overfitting bias

Cross-fitting is not a robustness check. It is a structural requirement for valid inference with ML nuisance estimators.

Without it: overfit residuals \(\Rightarrow\) biased score \(\Rightarrow\) invalid standard errors, even asymptotically.

With it: the orthogonality bound applies, \(\hat\tau\) is \(\sqrt{n}\)-consistent and asymptotically normal, and standard confidence intervals are valid.

Double/debiased machine learning (DML)

Putting the pieces together:

\[ \boxed{ \text{DML} = \text{Orthogonal (AIPW-type) score} + \text{Flexible ML nuisance estimators} + \text{Cross-fitting} } \]

DML is the recipe that lets you use random forests, lasso, boosting, or neural nets for \(\hat\mu(X)\) and \(\hat\pi(X)\) without sacrificing \(\sqrt{n}\)-consistency or valid standard errors.

It is an estimation technology. It answers “how do I flexibly model a high-dimensional \(X\)?” — not “is \(X\) the right adjustment set?”

What DML repairs

  • Misspecification bias from rigid parametric outcome or propensity models.
  • The need to hand-specify functional form and interactions in high-dimensional \(X\).
  • The tension between flexibility (needed for correct specification) and valid inference (needed for correct standard errors).

DML lets flexible prediction and valid causal inference coexist.

What DML does not repair

DML assumes conditional ignorability and overlap. It does not test, weaken, or substitute for them.

  • If \(X\) omits a confounder, DML estimates a precisely wrong number, with a tight, convincing-looking confidence interval.
  • If overlap fails, extreme \(\hat\pi(X)\) still destabilizes the estimator — flexible modeling does not create common support that is not in the data.
  • Flexible fit to \(X\) does not certify that \(X\) is a sufficient adjustment set.

\[ \boxed{ \text{Flexible nuisance estimation} \not\Rightarrow \text{Conditional ignorability} } \]

Diagnosing a DML analysis: questions to ask

Given a paper that reports a DML estimate:

  1. What is the claimed adjustment set \(X\), and is it defended on substantive grounds (Lecture 2), not just “we threw in everything and let the forest sort it out”?
  2. Was cross-fitting actually used, and how many folds?
  3. Is there any check on overlap — trimming, propensity diagnostics — analogous to Lecture 3?
  4. Does the paper report which specific ML method was used for each nuisance function, and does it matter?
  5. Would a much simpler AIPW estimator (with parametric nuisance models) give a similar answer?

In-class exercise

Consider three hypothetical DML analyses of the same observational comparison:

Analysis A

Rich \(X\), defended adjustment set; cross-fitting used; tight CI similar to a simpler parametric AIPW estimate.

Analysis B

Rich \(X\), “kitchen sink” adjustment set with no substantive defense; cross-fitting used; tight CI very different from any simpler estimate.

Analysis C

Rich \(X\), defended adjustment set; no cross-fitting; extremely tight CI.

For each: What has the analysis demonstrated? What remains uncertain? Is the problem identification, design, or estimation?

This week’s readings, in brief

Four papers, four roles:

  • Chernozhukov et al. (2018) — the paper that named DML: the general recipe and its canonical applications.
  • Athey, Imbens, and Wager (2018) — a contrasting debiasing strategy for a narrower (sparse linear) setting.
  • Kennedy (2024) — the semiparametric efficiency theory underneath AIPW and DML.
  • Ahrens et al. (2026) — a practitioner’s field guide to actually running DML.

Chernozhukov et al. (2018): the origin of the recipe

This is the paper that coined “double/debiased machine learning” and gave it its two-ingredient recipe — Neyman orthogonal scores plus cross-fitting — which is exactly what we built up today.

It formalizes the two failure modes of naive plug-in estimation:

  • regularization bias — first-order sensitivity of the score to nuisance error;
  • overfitting bias — dependence between \(\hat\eta\) and the very data used to evaluate the score.

It also distinguishes two cross-fitting estimators: DML1 solves the moment condition separately in each fold and averages the resulting \(\hat\theta_k\); DML2 pools the orthogonal score across all folds and solves once. DML2 is generally the more stable choice in practice.

Chernozhukov et al.: a menu of canonical applications

The paper works out Neyman orthogonal scores for four widely used estimands:

  • the coefficient in a partially linear regression (\(Y = \theta_0 D + g_0(X) + \varepsilon\));
  • the coefficient in a partially linear IV model;
  • the ATE/ATT under unconfoundedness (the interactive regression model — this is our AIPW setting); and
  • the LATE in an instrumental-variables design.

Takeaway: the same orthogonalize-and-cross-fit logic applies far beyond selection-on-observables — it is a general tool for any low-dimensional parameter defined alongside a high-dimensional nuisance function.

Chernozhukov et al.: the 401(k) example

Using SIPP data (Chernozhukov and Hansen 2004), they estimate the effect of 401(k) eligibility on net financial assets, controlling for age, income, family size, education, and other job-related covariates:

  • No controls: ATE \(\approx \$19{,}559\) (SE \(1{,}413\)) — not credible, given the confounding concern.
  • DML-controlled (partially linear model): ATE \(\approx \$8{,}200\)–\(9{,}200\), essentially the same across six different ML learners (lasso, regression tree, random forest, boosting, neural net, ensemble).

Agreement across very different learners is itself a diagnostic. Large disagreement across learners is a warning sign, not a modeling detail to average away.

Athey, Imbens, and Wager (2018): a different bet

Same motivating problem as today — unconfoundedness is more plausible with many covariates, but many covariates break standard estimation. Their example: does controlling only for age and sex vs. detailed medical histories change how credible unconfoundedness is for a flu-vaccine effect?

Their question: in a high-dimensional linear outcome model, do we need to estimate the propensity score at all?

Their answer: no. If \(\mu_d(X)\) is well approximated by a sparse linear model, \(\sqrt{n}\)-consistent inference is possible using only overlap — not a consistent \(\hat\pi(X)\), and not sparsity of the treatment effect itself.

Athey, Imbens, and Wager: approximate residual balancing

A two-stage procedure:

  1. Fit a regularized (lasso/elastic net) linear outcome model for \(Y\) on \(X\), separately in each treatment arm.
  2. Reweight the residuals using weights chosen not to fit a propensity model, but to approximately balance the covariate means between treated and control (following Zubizarreta 2015) — trading exact balance for controlled variance.

This directly corrects the shrinkage bias that regularized regression introduces, without ever estimating \(\pi(X)\).

Cost of the shortcut: it buys you out of the propensity model, but only by committing to linearity/sparsity in \(\mu(X)\) — a functional-form assumption DML’s AIPW-based approach does not require.

Kennedy (2024): the theory underneath AIPW

Read this one if you want to see the AIPW formula derived, not just asserted.

Kennedy frames estimation as targeting a functional \(\psi(P)\) and uses the von Mises (distributional Taylor) expansion:

\[ \psi(\hat P) - \psi(P) = -\underbrace{\int \phi(z;\hat P)\,dP(z)}_{\text{first-order bias}} + R_2(\hat P, P). \]

A naive plug-in estimator \(\hat\psi_{pi} = \psi(\hat P)\) inherits that first-order bias directly.

The fix — subtract an estimate of that bias term — gives the one-step estimator:

\[ \hat\psi = \psi(\hat P) + P_n\{\phi(Z;\hat P)\}. \]

For the ATE, this is exactly \(\hat\mu(X) + \dfrac{D(Y-\hat\mu(X))}{\hat\pi(X)} - \cdots\) — our AIPW score, now derived from the efficient influence function rather than pattern-matched from double robustness.

Kennedy: naming the two failure modes precisely

Kennedy decomposes the one-step estimator’s error into two terms:

\[ \hat\psi - \psi = \underbrace{(P_n - P)\{\hat\phi - \phi\}}_{T_1 \text{: empirical process term}} + \underbrace{R_2(\hat P, P)}_{T_2 \text{: remainder/regularization-bias term}}. \]

  • \(T_1 \to 0\) requires either low estimator complexity or sample splitting — this is cross-fitting’s job.
  • \(T_2 \to 0\) at rate \(o_P(n^{-1/2})\) requires an orthogonal influence function plus adequate nuisance convergence rates — this is Neyman orthogonality’s job.

This is the same regularization/overfitting distinction from Chernozhukov et al., now derived from first principles rather than asserted. The framework generalizes well beyond ATEs — to LATEs, stochastic interventions, and missing-data problems, using the same machinery.

Ahrens et al. (2026): the practitioner’s field guide

The newest and most applied of the four readings — written explicitly to help researchers use DML correctly.

Their running example, Dube et al. (2020) on monopsony power on MTurk, uses a partially linear regression with text-based task features as high-dimensional \(X\) — a case where no parametric functional form is defensible.

They contrast a naive score with the orthogonal (partialling-out) score:

\[ m_{naive}(W;\theta,\eta) = (Y - g(X) - \theta D)D, \qquad m_{PLM}(W;\theta,\eta) = \big[(Y-\ell(X)) - \theta(D-r(X))\big](D - r(X)). \]

Both identify \(\theta_0\). Only \(m_{PLM}\) is Neyman orthogonal — the same lesson as today’s naive-plug-in slides, now in a different application.

Ahrens et al.: practical recommendations for PS1

Their concrete guidance, directly relevant to your replication:

  • Folds: \(K=5\) or \(10\) is a reasonable default; more folds help but with diminishing returns.
  • Repeat cross-fitting across several random splits and report the spread — large variation across splits is itself a diagnostic, not just noise to average away.
  • Try multiple learners (parametric benchmark, lasso, trees, neural net); substantial disagreement across learners is a warning sign, not a detail to average over.

A caution that matters for your problem set: common ML defaults do not automatically satisfy DML’s convergence-rate requirements.

They cite evidence that random forests under standard tuning, and deep regression trees, can fail to converge fast enough for DML’s guarantees to hold. “We used a random forest” is not, by itself, a valid DML analysis.

The central lesson

Double/debiased machine learning is a solution to a statistical problem: how to use flexible estimators without breaking \(\sqrt{n}\)-inference.

It is not a solution to the identification problem from Lectures 1–2.

\[ \boxed{ \text{Cross-fitted, orthogonal, ML-based estimation} \not\Rightarrow \text{conditional ignorability holds} } \]
